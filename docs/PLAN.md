# План развития форка cosmic-ext-classic-menu-plus

Форк: `shagovAlexei/cosmic-ext-classic-menu-plus` (переименован из `cosmic-ext-classic-menu`, свой APP_ID, конфиг и D-Bus имя) ← `championpeak87/cosmic-ext-classic-menu` (remote `upstream`).
Дата: 2026-09-25. Архитектура проекта описана в `CLAUDE.md`.

## Цели

1. **Гибернация.** Кнопка в ряду питания и подтверждение внутри попапа. Заменяет отдельный апплет `~/Projects/applet-hibernate` и скрипт `hibernate-confirm` (zenity).
2. **Кнопки питания.** Пользователь выбирает, какие кнопки показывать и в каком порядке.
3. **Размеры.** Ширина и высота попапа, размер иконок приложений, плотность списка.
4. **Избранное.** Категория «Избранное» первой в списке и открыта по умолчанию. Закрепление через ПКМ, порядок задаётся в настройках.
5. **Категории.** Свои категории (название и иконка), перенос и скрытие приложений, скрытие и порядок стандартных категорий.

## Принципы

- Изменения должны оставаться совместимыми с upstream при слиянии. `APP_ID` теперь `io.github.shagovAlexei.cosmic-ext-classic-menu-plus` (см. ветку `chore/rename-plus`) и дальше не меняется. Существующие поля конфига не трогаем, новые добавляются в `AppletConfig` с `Default`, `#[version = 1]` остаётся. Старые конфиги читаются без миграции: отсутствующие ключи получают значения по умолчанию.
- Одна функция — одна ветка `feat/<name>`, слияние в `master` форка. Гибернацию и выбор кнопок можно предложить upstream отдельными PR.
- Быстрые действия доступны через ПКМ по приложению, полное управление — в приложении настроек.
- Новые строки i18n добавляются как минимум в `en` и `ru`.
- Чистую логику (разрешение категорий, фильтрация, порядок) выносим в функции без UI и покрываем unit-тестами. UI проверяем вручную: `just build-release && sudo just install` и перезапуск `cosmic-panel`.

## Изменения конфига (`applet/src/config.rs`)

Все поля новые и имеют значения по умолчанию, указанные ниже.

| Поле | Тип | По умолчанию | Функция |
|---|---|---|---|
| `power_buttons` | `Vec<PowerAction>` | `[Logout, Suspend, Hibernate, Lock, Reboot, Shutdown]` | 1, 2 |
| `popup_width` | `u32` | `600` (как сейчас) | 3 |
| `popup_height` | `u32` | `700` (как сейчас) | 3 |
| `app_icon_size` | `u16` | текущий размер (`space_l`) | 3 |
| `list_density` | `ListDensity { Compact, Normal }` | `Normal` | 3 |
| `pinned_apps` | `Vec<String>` (app id, в порядке показа) | `[]` | 4 |
| `custom_categories` | `Vec<CustomCategory { id, name, icon }>` | `[]` | 5 |
| `app_category_overrides` | `HashMap<String /*app id*/, String /*category key*/>` | `{}` | 5 |
| `hidden_apps` | `Vec<String>` | `[]` | 5 |
| `hidden_categories` | `Vec<String>` (category key) | `[]` | 5 |
| `category_order` | `Vec<String>` (category key) | `[]` (пустой = стандартный порядок) | 5 |

`PowerAction` получает `Serialize, Deserialize, Copy`.

**Ключ категории** (`category key`) — стабильная строка:
- `favorites`, `all-applications`, `recently-used` для служебных категорий;
- freedesktop-имя для стандартных (`Audio`, `Game`, …);
- `custom:<id>` для пользовательских (`id` генерируется при создании и не меняется при переименовании).

## 1. Гибернация

- `PowerAction::Hibernate`.
- `power_options::hibernate()` вызывает `ManagerProxy::hibernate(true)`.
- **Доступность.** При `init` выполняется асинхронный запрос `ManagerProxy::can_hibernate()`. Если ответ `na` или `no`, кнопка скрыта. Результат хранится в `Applet::can_hibernate: bool`.
- **Подтверждение.** Состояние `Applet::pending_confirmation: Option<PowerAction>`. Нажатие «Гибернация» заполняет его, и в ряду кнопок вместо иконок появляется строка «Перейти в гибернацию? [Отмена] [Да]». «Да» закрывает попап и выполняет действие. «Отмена», закрытие попапа или повторное открытие сбрасывают состояние. Остальные кнопки ведут себя как раньше (Logout/Reboot/Shutdown подтверждаются через `cosmic-osd`).
- **Иконка.** Символьной `system-hibernate-symbolic` в системе нет. Нужно добавить SVG в `res/icons/bundled/` (взять из Adwaita или нарисовать в стиле остальных иконок, с совместимой лицензией).
- **Flatpak.** Обёртка `flatpak-spawn` не нужна: logind вызывается по D-Bus напрямую, как Suspend и Lock.

## 2. Выбор и порядок кнопок питания

- `create_power_menu` строится из `config.power_buttons`. Hibernate дополнительно фильтруется по `can_hibernate`. Дубликаты отбрасываются. Неизвестное значение в конфиге (ручная правка, откат версии) сбрасывает список к умолчанию.
- **Настройки**, раздел «Кнопки питания»: список всех 6 действий, у каждого переключатель «показывать» и кнопки ↑/↓. Порядок хранится вместе с видимостью: в `power_buttons` лежат только видимые, в нужном порядке. Скрытые в UI настроек показываются в конце списка.
- Если выключены все кнопки, ряд питания не отображается.

## 3. Размеры и иконки

- В `AppletMenu::view_main_menu_list` вместо захардкоженных `600` и `POPUP_MAX_HEIGHT` используются `config.popup_width` и `config.popup_height`. Значения ограничиваются диапазонами: ширина 500–1200, высота 400–1200. `Limits` берутся из тех же значений.
- `VirtualizedAppList`:
  - высота строки: `Normal` = `space_xl` (как сейчас), `Compact` ≈ `space_l`, плюс поправка на `app_icon_size`, если иконка больше строки;
  - высота считается **одной функцией** `item_height(config)`, которую используют и рендер, и расчёт прокрутки (и навигация стрелками, если она зависит от высоты);
  - в режиме `Compact` строка с описанием (comment) скрыта.
- **Настройки**, раздел «Внешний вид»: `spin_button` для ширины, высоты и размера иконки (16–64); dropdown для плотности.

## 4. Избранное

- Служебная категория `ApplicationCategory::FAVORITES` (ключ `favorites`, иконка `starred-symbolic`, её нужно добавить в bundled).
- Порядок показа определяется `pinned_apps`. Удалённые из системы приложения молча пропускаются.
- **Открытие меню.** Если `pinned_apps` не пуст, выбрана «Избранное», иначе «Все приложения». Сейчас `toggle_popup` жёстко выставляет `ALL`.
- **ПКМ по приложению.** Чекбокс «В избранное» рядом с «Закрепить на панели». Меню приложения сейчас собирается дублирующимся кодом в двух местах (`applet.rs`, обработчики `UpdateAvailableApplications` и `PinToAppTrayIndex`). Выносим в одну функцию `build_app_context_menu(app, index, state)` в `applet_menu.rs`.
- Изменение записывается в конфиг через `write_entry`. Список обновляется сразу, если открыта «Избранное».
- **Настройки**, раздел «Избранное»: список закреплённых приложений (иконка и имя), кнопки ↑/↓ и «Открепить».

## 5. Категории

**Модель.** `ApplicationCategory` переходит от `&'static` констант к данным времени выполнения: `key: String`, `name: CategoryName { Localized(&'static str) | Custom(String) }`, `icon: CategoryIcon { Bundled(&'static [u8]) | Named(String) }`, `kind: Permanent | Standard | Custom`. Константы превращаются в функции-конструкторы. Ветку upstream `feat/custom-categories` (черновик на `Cow`) смотрим перед началом, чтобы не расходиться без нужды.

**Разрешение (чистая функция, покрыта тестами):**
`resolve_categories(apps, config) -> Vec<ApplicationCategory>`
1. Служебные: `favorites` (только если есть закреплённые), `all-applications`, `recently-used`.
2. Стандартные категории, в которых есть хотя бы одно видимое приложение с учётом переопределений.
3. Пользовательские категории (показываются, даже если пусты, чтобы можно было перенести в них первое приложение).
4. Убираются ключи из `hidden_categories`. Служебную «Все приложения» скрыть нельзя.
5. Применяется `category_order`. Ключи, которых в нём нет, идут после в стандартном порядке.

`apps_of_category(key, apps, config)`:
- `hidden_apps` исключаются везде, в том числе в «Все приложения» и в поиске. Вернуть приложение можно через настройки.
- Если у приложения есть запись в `app_category_overrides`, оно показывается **только** в этой категории, а не в исходных из `.desktop` («перенос»). В «Все приложения», «Недавние» и «Избранное» оно остаётся.
- Если категория из переопределения удалена, приложение возвращается в исходные категории.

**ПКМ по приложению:**
- «Переместить в…» — кнопка, по нажатию которой панель категорий внутри главного попапа заменяется списком стандартных и пользовательских категорий (с «Отмена»), плюс пункт «Вернуть исходную категорию». Не подменю: см. решения ниже.
- «Скрыть из меню».

**Разделитель в панели категорий.** Сейчас он вставляется жёстко после индекса 2. Надо вставлять после последней служебной категории.

**Настройки**, раздел «Категории»:
- список всех категорий в итоговом порядке: переключатель видимости, ↑/↓, для пользовательских ещё «Переименовать», «Иконка» (выбор из набора bundled и именованных symbolic-иконок) и «Удалить»;
- кнопка «Новая категория»;
- подсписок «Скрытые приложения» с кнопкой «Вернуть»;
- подсписок «Перенесённые приложения» с кнопкой «Сбросить».

**Структура приложения настроек.** Разделов становится пять (Общие, Внешний вид, Кнопки питания, Избранное, Категории). Переводим `settings/src/app.rs` на `nav_bar` со страницами и разносим страницы по модулям `settings/src/pages/*.rs`. Сейчас это один файл с одной секцией.

Решения, уточняющие раздел «Категории» выше:
- Служебные категории (Избранное, Все приложения, Недавние) всегда идут первыми в фиксированном порядке; `category_order` переставляет только стандартные и пользовательские. «Недавние» можно скрыть, «Все приложения» — никогда.
- `app_category_overrides: BTreeMap<String, String>` (не `HashMap`) — стабильный порядок в файле конфига.
- Id пользовательской категории — `next_custom_id` даёт `"c{N}"`, следующий свободный номер.
- Удаление пользовательской категории (`remove_custom_category`) чистит переопределения, `hidden_categories` и `category_order`, указывающие на неё.
- «Сбросить настройки» в приложении настроек сохраняет `pinned_apps` и все пять полей категорий — это данные, настроенные вручную, а не внешний вид.
- «Переместить в…» не может быть `menu::Item::Folder`: подменю открывает вложенный `xdg_popup`, libcosmic уничтожает попапы не в том порядке (`xdg_popup was destroyed while it was not the topmost popup`), и `cosmic-comp` паникует (`DeadResource`), перезапуская всю сессию COSMIC. Поэтому список категорий рисуется внутри главного попапа (`Applet::moving_app`), новых Wayland-поверхностей нет. Правило: в меню апплета не использовать `Folder` и другие вложенные попапы.
- `ContextMenuAction` обязан быть `Copy` (ограничение `menu::Action`), поэтому «Переместить в…» передаёт индекс в `Applet::move_targets`, а не саму категорию.
